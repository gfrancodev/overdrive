# Receiving Code Review

Evaluate each finding against the code, spec, established architecture, tests, and relevant validated experience.
Do not perform agreement.

- Reproduce or verify technical claims.
- Accept correct findings and fix the underlying issue.
- Reject or narrow findings that contradict requirements or project conventions, with evidence.
- When feedback exposes an architectural decision gap, update the ruling/spec if needed before propagating the change.
- Treat repeated verified reviewer feedback as a possible Experience Engine lesson, not an automatic global rule.
- Re-run relevant verification after fixes; durable capture happens only after evidence exists.
